# Migration beim Start, Schnappschüsse in stabilem Format

Jede JSON-Datei trägt ihre Schemaversion je Modul bzw. Baustein der Datenebene (`"schema": "<modul>/<n>"`). Beim Start sichert MoarCoal das ganze Datenverzeichnis als zeitgestempeltes Archiv und migriert dann alle Dateien auf den aktuellen Stand; schlägt das fehl, startet die App nicht und nennt die Datei. Der Code kennt danach nur das aktuelle Format, also keine Lese-Weichen für Altversionen, die über Jahre mitwachsen. Verworfen: Migration beim Lesen (Altformate leben unbegrenzt weiter) und Migration nur auf Knopfdruck (Code müsste alte Formate trotzdem lesen).

Schnappschüsse werden nicht migriert. Ihr Format ist klein und bewusst stabil (Schlüssel, Beträge, Einzelposten, Fundstellen als Klartext). Ändert es sich doch einmal, wird mitmigriert und die Werte vorher und nachher werden verglichen. Umbenannte Schlüssel im Wertekatalog: Verweise in Arbeitsdaten schreibt die Migration um; nur wenn ein Schnappschuss den alten Schlüssel enthält, führt der Katalog ihn unter `früher`, und zwar direkt beim aktuellen Schlüssel, ohne Ketten. Der Testkern meldet Aliasse, auf die kein Schnappschuss mehr verweist. Entfallene Schlüssel werden markiert statt gelöscht. Siehe [Schema-Evolution](https://github.com/oiff2/MoarCoal/issues/15).
